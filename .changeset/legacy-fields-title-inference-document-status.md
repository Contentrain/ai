Four fixes for models and content that predate the current rules, from issues #116, #120, #124 and #125.

- **Legacy field names are grandfathered (#116).** `contentrain_model_save` enforced snake_case on every field of every save, so a model carrying one pre-rule `creativeWork` field was read-only through MCP — even a one-line `title_field` correction was refused. The existing model is now read first; a name it already has is kept and reported as a `schema_warning`, while a *new* camelCase field is still rejected. `contentrain_validate` lists such fields as notices, so the two validators agree on what a valid model is.
- **`title_field` backfill matches Studio's resolver (#120).** `validate --fix` picked an optional `title` over a required `name` (name-likeness outranked requiredness), and titled a settings singleton by its `whatsapp_url`. Requiredness is now the first tiebreak on every rung, and slug/url/code fields are never inferred — they remain legal when an author names them. When only such fields exist, the error names them and asks for an explicit choice instead of guessing.
- **`contentrain_bulk update_status` supports document models (#124).** Documents are addressed by `slugs`, the same identity `contentrain_content_save` uses; `entry_ids` stays for collections, and singletons/dictionaries take neither. Each wrong combination is rejected with a message naming the right one.
- **`publish_at`/`expire_at` live in meta only (#125).** `contentrain_content_save` merged them into the entry's data, so they leaked into document frontmatter and collection JSON — and documents merge frontmatter on save, so nothing could remove them. They now ride on the entry, `null` clears a date, an omitted key leaves it unchanged, and the response says plainly that status is unchanged (the dates gate delivery of a *published* entry; a past `publish_at` never publishes a draft). `contentrain_validate` warns about frontmatter copies an earlier version left behind, and `fix: true` strips them when meta holds the same key.
